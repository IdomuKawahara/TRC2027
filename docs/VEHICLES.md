# 機体の切り替え: 過去機体でも同じプログラムを使う

本番機ができるまで過去機体でコードを確認する、というように、**機体が変わっても同じプログラムを使える** ようにする仕組みです。
触るのは **`main/mission/config.py` の 1 ファイルだけ** です。

**手順だけを知りたいときは [`VEHICLE_SETUP_GUIDE.md`](VEHICLE_SETUP_GUIDE.md)** (過去機体はプログラムの確認用、本番機で値を調整、という進め方の手順書) を見てください。

## 1. 仕組み

```python
# ===== config.py の一番上 =====
VEHICLE = "honban"    # ← 過去機体で試すときだけ "old" に書き換える

# ...(今までの設定。これが本番機の値)...
FIG8_SPIN_SEC = 8.0

# ===== config.py の一番下 =====
if VEHICLE == "old":
    # 過去機体だけ違う値 (行頭の # を外すと有効)
    FIG8_SPIN_SEC = 12.0
    PIN_AIN1 = 5
```

- `VEHICLE = "honban"` (本番機) のときは、config.py の値そのままで動きます。一番下の `if` の中は使われません。
- `VEHICLE = "old"` (過去機体) のときは、一番下の `if VEHICLE == "old":` の中に書いた値だけが置き換わります。書いていない値は本番機と同じです。
- BNO055 のキャリブレーション結果は、機体ごとに別のファイルに保存されます。
  - 本番機: `config/bno055_calib_honban.json`
  - 過去機体: `config/bno055_calib_old.json`

## 2. 過去機体で試すときの手順

1. `main/mission/config.py` の一番上を `VEHICLE = "old"` にする
2. config.py の一番下の `if VEHICLE == "old":` の中に、過去機体で違う値を書く (下の 3 章)。例が `#` 付きで書いてあるので、行頭の `#` を外して値を直す
3. `python3 tools/motor_test.py` で前進・後退の向きを確認
4. `python3 tools/bno055_calibrate.py` で **過去機体のキャリブレーションを取る** (保存先は自動で `config/bno055_calib_old.json` になります)
5. `python3 tools/vehicle_measure.py` で旋回の速さを測る (★モータが動きます)。最後に「今の値 → 目安の値」の一覧が出て、「config.py に書き込みますか？」と聞かれるので、よければ `yes` と入力すると `if VEHICLE == "old":` の中に書き込まれる (`yes` 以外なら何も変えない)
6. `python3 main/main.py` で走らせる。起動ログの最初に `機体: old`、変えた値の一覧、試験用機体の警告が出ます

書き間違いがあると、手順 3〜6 のどれを起動してもすぐエラーで止まります (下の「書き間違い」の行)。

### 本番機に戻すとき (★忘れると本番で過去機体の設定のまま走ります)

config.py の一番上を `VEHICLE = "honban"` に戻すだけです。一番下の `if VEHICLE == "old":` の中は消さなくて構いません (本番機では使われません)。

確認: `grep '^VEHICLE =' main/mission/config.py` が `VEHICLE = "honban"` と出れば OK。
自動テスト (`python3 test/run_all.py`) も、config.py が `"honban"` になっていないと ❌ になります。

## 3. 機体が違うと起きる問題と対策

| 起きる問題 | 対策 (入れてある仕組み) | 機体ごとにやること |
|---|---|---|
| **別の機体のキャリブレーション結果を使ってしまう** → 方位がずれたまま「キャリブレーション済み」として走る | 結果は機体ごとに別のファイル。ファイルに **機体名と BNO055 の固有 ID** を記録し、起動時に今の機体・今のセンサと違えば **書き込まずに** Phase3 で通常どおりキャリブレーションする | 機体ごとに `tools/bno055_calibrate.py` を 1 回 |
| **モータの配線が違う** (前進で後ろに進む・左右が逆) | ピン番号を `if VEHICLE == "old":` の中で変えられる | 後ろに進む側は IN1 と IN2 を入れ替え。左右が逆なら A と B の組を入れ替え。`tools/motor_test.py` で確認 |
| **旋回・走行の速さが違う** → 秒数で決めている動き (Phase3 のスピン 8 秒、Phase5 の探索パルス 0.25 秒など) が合わない | `tools/vehicle_measure.py` で実際に測り、その機体に合う値を表示する | 表示された一覧を確認して `yes` で書き込む |
| **機体が遅い** → GPS の進行方位が使われない / 進んでいるのにスタックと誤判定 | 同上 (`HEADING_COG_MIN_SPEED_MPS`, `STUCK_NOPROGRESS_SEC` の目安を出す) | 同上 |
| **センサの取り付け向きが違う** (BNO055 の向き・カメラが上下逆かどうか) | `BNO_ORIENTATION`, `CAM_ROTATE_180` を機体ごとに設定 | `tools/phase5_live.py` で右に置いた物が右と表示されるか確認 |
| **センサが付いていない** | 気圧センサ: `BMP180_REQUIRED = False` で、無くても起動する (今のミッションは気圧を使っていない)。カメラ: Phase5 は自動で超音波スキャンに切り替わる。Phase4 の見張りは `CAM_P4_ENABLE = False` で止める | 無いセンサを書く |
| **超音波の取り付け位置が違う** → 0m の判定距離が合わない | `GOAL_SONAR_DIST_M` を機体ごとに設定 | 先端をゴールに当てたときの超音波の値 + 2〜3cm |
| **過去機体には分離機構 (フック) が無い** → Phase2 で分離を検知できない | Phase2 のプログラムは変えていない。分離を検知できなくても 30 秒で先に進む | 待ち時間を短くしたければ `PHASE2_BACK_TIMEOUT_SEC` を過去機体だけ変える |
| **地上試験のたびに落下検知を 7 分待つ** | `FALL_TIMEOUT_SEC` などを過去機体だけ短くできる (本番機の値は変わらない) | 例の 5 番 |
| **設定の書き間違い** → 違うピンでモータを回す・値が効かないまま走る | 起動時にエラーで止める。config.py に無い名前 (打ち間違い。近い名前を教えてくれる)・型の違い (数値の所に文字、`True` の所に `0` など)・計算で決まる値 (`WEAK_RATIO` など) の直接変更は受け付けない | エラーの文を読んで直す |
| **本番で過去機体の設定のまま走る** | 過去機体では起動時に「試験用の機体」と警告。自動テストでも config.py が `"honban"` か確認する。BNO055 が別物ならキャリブレーション結果は使われない | 本番前に config.py の一番上を確認 |
| **どの機体のログか分からなくなる** | ログの最初に機体名と本番機との違いを表示。CSV のファイル名に機体名が入る (`mission_old_日時.csv`) | — |
| **過去機体に切り替えたまま自動テストを回して結果が変わる** | 自動テストのシミュレーションは常に本番機の設定で動く | — |

### 過去機体で確認できること・できないこと

- **できる**: プログラムの流れ (フェーズの切り替え)、GPS 誘導、方位の融合、スタック検知と回避の動き、カメラの色検知、ログ
- **できない (本番機でやり直す)**: キャリブレーション、旋回・走行の速さに合わせた値、超音波の 0m 判定距離、分離機構の動作、カメラの見え方 (取り付け高さ・向き)

過去機体で調整した値は `if VEHICLE == "old":` の中にしか入らないので、**本番機の設定には混ざりません**。
逆に、過去機体で「この値は機体に関係なく良かった」と分かったものは、config.py の上の方 (本番機の値) を書き換えてください。

## 4. 書き方の注意

```python
if VEHICLE == "old":
    PIN_AIN1 = 5               # 整数
    CAM_ROTATE_180 = False     # True / False (先頭は大文字)
    FIG8_SPIN_SEC = 12.0       # 数値
    CAM_SIZE = (320, 240)      # 並びは ( ) で囲む
    pass                       # ← 消さない (中が全部 # のときに必要)
```

- `if` の中は **行頭を 4 文字下げる** (下げないと `if` の外になり、本番機にも効いてしまう / エラーになる)。
- 書ける名前は config.py の上の方にあるものだけです。
- ほかの値から計算される値 (`WEAK_RATIO`, `MAG_DECLINATION` など) は直接は変えられません。元の値 (`SPEED_WEAK`, `MAG_SITE` など) を変えると自動で計算し直されます。
- 3 台目の機体を足すときは、一番上の `VEHICLES = ("honban", "old")` に名前を足し、一番下に `if VEHICLE == "名前":` の組を足します。

## 5. 実機で未確認のこと

- BNO055 の固有 ID の読み取りは、偽のセンサでのテストだけで、実物では確認していません。読めなかった場合は ID の確認を飛ばして機体名だけで判断するので、動作は止まりません。起動ログの `センサ固有 ID:` で読めているか分かります。
- `tools/vehicle_measure.py` はモータを動かすため、作成時には実行していません (計算部分と config.py への書き込み部分だけ、config.py のコピーでテスト済み)。

### vehicle_measure.py の書き込みについて

- 書き込むのは `yes` と入力したときだけです (`--yes` を付けてもこの確認は省略されません)。
- 本番機 (`VEHICLE = "honban"`) で測ったときは、config.py の上の方の本番機の値を書き換えます (説明のコメントは残ります)。
- 過去機体では `if VEHICLE == "old":` の中に書きます。同じ名前の行 (`#` 付きの例を含む) があれば置き換え、無ければ足します。行の最後に `# vehicle_measure.py で測定 (日付)` と付きます。
- 書き込んだあと config.py を読み込み直して確かめ、読み込めなければ自動で元に戻します。
- 変わった所は `git diff main/mission/config.py`、元に戻すには `git checkout main/mission/config.py`。
