## 1. 参考チームの手法(調査結果)

### YutakaOkutani/cansat-system(先輩)
| 項目 | 内容 |
|---|---|
| 色検知 (`lib/cone_detect.py`) | 赤の HSV 2レンジ (H 0〜16 / 165〜179)。さらに YCrCb・Lab でも赤判定して組み合わせる。gray-world 白補正・CLAHE。画面の明るさ (V の中央値) で S/V 閾値を自動調整 |
| カメラ | Picamera2, 640x480, "RGB888"(配列は B,G,R 順), 取付が逆なので 180°回転 |
| 到達判定 | 赤の占有率 ≥ 10% かつ画面端に接触 |
| 0m 確認 (`mission/goal.py`, `phases/p6.py`) | カメラで中央に捉え、**超音波 60cm 以内で近接モード**。**停止して複数回測定 → 中央値**、ばらつき・測定の新しさ・カメラと超音波の時刻ずれもチェック。0.15 秒のパルス前進 → 0.3 秒静止の繰り返し。停止距離 3cm |

### FROM-THE-EARTH/F.T.E.15th(NSE2025 Re-Star-t)
| 項目 | 内容 |
|---|---|
| 色検知 (`library/detect_corn.py`) | 見本画像 (ROI) のヒストグラム逆投影 → 大津の二値化 → 膨張 → 連結成分 |
| 操舵 | 最大候補の重心 x (0〜1) が 0.6 超→右, 0.4 未満→左, それ以外→前進 |
| 到達判定 | 色領域が画面の 1/25 を超えたら到達 |
| 見失い | 探索フェーズへ戻りその場旋回 |

### 他の強豪チーム(Web 調査)
- ARLISS 等の報告書でも「ゴールの赤色を検知して、その方向に走る」が定番。
- 課題は **天候による明るさ変化で色検知の精度が落ちる** こと(→ 明るさ適応閾値で対策)。深層学習で認識率を上げたチーム (ARLISS2019 0m 達成) もあるが、Pi Zero 2 W のメモリでは重い。
- 参考: [IEICE 論文: Deep Learning を用いた CanSat の 0m 誘導](https://search.ieice.org/bin/summary.php?id=j104-d_7_540), [ARLISS2024 報告書 (SuperNOVA)](https://unisec.jp/history/arliss2024/16_SuperNOVA.pdf), [ARLISS2022 報告書 (Tokyo Manji Union)](https://unisec.jp/history/arliss2022/ARLISS2022_tokyo_manji_union.pdf)

### 採用した組み合わせ
- 色検知: cansat-system の **HSV 2レンジ + 明るさ適応閾値** に、茶色い土を除外する **R と G,B の比率条件** を追加
- 操舵: F.T.E. の **重心 x で左右判断** を、ずれに比例した長さの旋回パルスに改良
- 0m 確認: cansat-system の **停止して超音波を複数回 → 中央値・ばらつき** 方式

```
Phase5 開始 → カメラ起動 (失敗 → 超音波スキャンへ)
  ┌─ 停止 → 撮影 → 色検知 ───────────────────────────────┐
  │ 見えない : 最後に見えた側へ小刻みに旋回 (約1周で少し前進して視点変更)
  │            6周探しても無い → 超音波スキャンへ
  │ 見える   : ずれに比例して旋回 / 正面なら前進 (近いほど短く)
  │ 近い     : (カメラで大きい or 超音波 ≤ 0.40m) → 停止して確認 ↓
  └──────────────────────────────────────────────────────┘
  確認: 超音波 5 回 + カメラ 1 枚
    CONFIRMED (中央値 ≤ 0.08m & カメラも近い) → 0.3 秒押し込み → 再確認 → 0m 到達 ✅
    BLIND (カメラは接触寸前なのに超音波が測れない = 不感帯の疑い)
          → 0.25 秒後退して測り直し、≤ 0.20m なら押し込み → 再確認 → 0m 到達 ✅
    FAR   → 前進を続ける (カメラ接触寸前なのに FAR が 5 回続いたら下がって再接近)
    OBSTACLE (超音波は近いがカメラ上のゴールは小さい) → 回避
```

### `sensor/goal_vision.py`(新規)
- `ColorGoalDetector(backend="auto")`: OpenCV があれば OpenCV 版、無ければ numpy 版
  - **OpenCV 版(追記)**: INTER_AREA 縮小 + ぼかし → HSV → 画素単位のオープン/クローズ処理 → `connectedComponentsWithStats` → **形状判定**(縦長か・下が広いか・塗りつぶし率)で、地面の赤いテープ・横長の赤い物・逆三角形・枠状の物など**コーンらしくない赤を除外**。近距離・画面端で切れている・小さい(高さ 14px 未満)領域は形が分からないので形状判定しない。1 枚 **24ms**(実測)
  - numpy 版: 8×8 セル単位の近似ラベリング(形状判定なし)。1 枚 81ms(実測)。OpenCV が壊れたときの保険
  - OpenCV は import だけで約 40MB 使うため、**Phase5 で検知器を作るときに初めて読み込む**(Phase0〜4 のメモリは増えない)
- `decide_steer()`: 検知結果 → 次の 1 パルス(左/右/前進と秒数)
- `summarize_sonar()`, `judge_goal()`, `judge_backoff()`, `judge_after_push()`: 超音波によるゴール確認の判定(純粋関数でテスト可能)
- `PiCameraCapture`: Picamera2 で 1 枚ずつ取得。**IMX219 の全画角モード (1640x1232) を明示指定**(指定しないと 640x480 の中央クロップで画角が狭くなる。実機の rpicam-still で実際にクロップモードが選ばれることを確認した)
- 単体実行: `python3 sensor/goal_vision.py 画像.jpg --save-debug 結果.jpg --save-mask マスク.png`

### 単体テストの内容 (`test_goal_vision.py`)

- (OpenCV 版のみ) OpenCV の HSV と自作 HSV の一致 / 台形のコーン → 採用・形状スコア高 / 白い反射帯で割れたコーン → 1 つの領域 / **地面の赤い帯・逆三角形・中抜きの枠 → 除外** / 面積の大きい横長の赤よりコーンを優先 / 近距離・画面端の領域は形状判定しない / 約 9m 先の小さいコーンも検出

## 5. 実機を動かさずにコードを読んで確認したこと(モータ・GPIO)
- Phase4 の「後退禁止ロック」は Phase4 終了時 (`finally`) に解除される → Phase5 の後退パルス(不感帯対策・再接近)は実際に後退する。
- `MotorController.stop()` はソフトスタートをリセットするため、Phase5 の**各パルスは毎回デューティ 80% から始まる**(パルスが短いので 100% には上がらない)。
- `turn_*_strong` は片輪だけ回す旋回なので、その場回転ではなく止まった車輪を軸に回る。カメラ位置が少し横にずれるが、毎回撮り直すので問題は小さいはず。
- 超音波 (`SonarSensor`) はビジーウェイト。Phase5 では他スレッドから同時に呼ばれない(GPS スレッドとモータのソフトスタートスレッドのみ並走)。確認時は 60ms 間隔で 5 回測定。
- カメラは CSI 接続なので GPIO のピン(モータ・超音波・LED)とは競合しない。
- カメラは **Phase5 開始時に初めて起動**(Phase0〜4 の間はメモリを使わない)し、終了時・フォールバック前に必ず解放する。

## 6. 実機でしか確認できず、未検証の項目
1. **赤いコーンを実際に検知できるか**(撮影時は夜間で真っ暗だった)。屋外の晴天・曇天・逆光での検知
2. **赤と青が入れ替わっていないか**(`CAM_SWAP_RB`)。picamera2 の "RGB888" は B,G,R 順なので並べ替えているが、暗い画像では確認できなかった
3. カメラの取り付け向き(上下逆なら `CAM_ROTATE_180 = True`)・左右の向きが正しいか(コーンが右に写る → 右に旋回するか)
4. **パルスの長さで機体が実際に動くか**(0.08 秒の旋回は芝の上だと静止摩擦で動かない可能性)。1 回の探索旋回で何度回るか (`CAM_SEARCH_PULSES_PER_LAP`)
5. **超音波の取り付け位置と `GOAL_SONAR_DIST_M = 0.08`**: 機体の先端がコーンに触れたとき超音波が何 m を示すか / 何 cm 以下で測れなくなるか(不感帯)
6. 超音波がコーン(円錐で斜め)に当たって正しく反射するか
7. Phase5 全体を main2.py で動かしたときのメモリ(カメラ + OpenCV 単体ではピーク 60MB を確認済み。GPS スレッド等と合わせた実走時は未確認)と 1 ループの所要時間
9. **形状判定が本物のコーンを落とさないか**(白い反射帯が太い・一部が草で隠れる・斜めから見る など)。落とすようなら `CAM_SHAPE_MIN_SCORE` を下げる(0 で形状判定なし)
8. Phase4 → Phase5 の切り替え半径 `PHASE4_TO_5_RADIUS = 2.0 m` は**変更していません**。GPS 誤差が数 m あるので、カメラ方式では 5m 程度に広げた方が良い可能性あり(要実験)

## 9. 追加変更 (2026-11-07): カメラ上下逆の取り付け / 見つからないときの GPS への戻り

### カメラを上下逆に取り付ける
- `CAM_ROTATE_180 = True` を既定にした。画像を 180° 回転 (= 上下と左右を両方入れ替え) してから検知する。
- 左右だけの入れ替えにしなかった理由: 上下逆の取り付けでは画像の上下も逆になる。左右だけ直すとコーンが逆さま (逆三角形) に写り、OpenCV 版の形状判定で「コーンではない」と除外されてしまう。
- `test/test_phase5_live.py` は既定で 180° 回転する。カメラを機体から外して正立で持って試すときは `--no-rotate`。

### 1周してもゴールが見つからないとき → 少し移動して Phase4 (GPS 誘導) へ戻る
- **「1周」は BNO055 の地磁気で実際に 360° 回ったかで判定**する (`CAM_SEARCH_LAP_DEG`)。モータ通電中は地磁気が乱れるため、止まっているときに 3 回読んで平均する。地磁気が読めないときは旋回 24 回で判定 (`CAM_SEARCH_PULSES_PER_LAP`)、地磁気で測っていても 48 回で打ち切る (保険)。
- 1周しても見えなければ、2 秒前進 (前が塞がっていれば旋回) してから Phase4 へ戻る。
- **戻った Phase4 は最低 10 秒 GPS 誘導で走ってから Phase5 へ移る** (`PHASE4_REENTRY_MIN_SEC`)。戻った直後は GPS 上まだ 2m 以内のため、この条件がないとすぐ Phase5 に戻って同じ場所で探し直すだけになる。
- 行き来は最大 3 回 (`PHASE5_MAX_RETURNS_TO_GPS`)。上限に達したら最後の Phase5 は GPS に戻らず、従来どおり探索を続けて 6 周で超音波スキャンへ。
- `main()` の Phase4 → Phase5 を `run_phase4_and_5()` にまとめた。Phase5 に BNO055 を渡すようになった。

### テスト (追加分)
| テスト | 結果 |
|---|---|

| BNO055 なし / BNO055 が読めない → 旋回 24 回で 1 周と判定して戻る | ✅ |
| 前が塞がっているときは前進せずに旋回してから戻る | ✅ |
| 1周の途中でコーンを見つけたら戻らずに 0m 到達 | ✅ |
| Phase4 ⇄ Phase5 の行き来: 戻った Phase4 に最低走行時間が渡る / 上限 3 回で最後は戻らない / 戻った Phase4 がタイムアウトしたら終了 | ✅ |
| カメラ設定が 180° 回転になっている | ✅ |
| 既存テスト「押し込み後にコーンが離れた」: 以前はタイムアウトで終了 → 今は「見えない → 1周 → GPS へ戻る」になったので、期待値を「成功にしない」に変更 | ✅ |
